playwright-cli-demo · CI architecture

Bounded Healing Architecture

Two Copilot-CLI pipelines generate and repair Playwright tests automatically — one for brand-new coverage, one for the regression suite. Neither can ever bypass the one gate that decides what actually merges.

01 — System map

One gate, two automated pipelines feeding it

playwright.yml is the only thing that decides pass/fail. Both pipelines below only ever produce a PR for a human to merge — the gate re-runs on that PR independently, so nothing either pipeline does can change what "passing" means.

02 — Net-new coverage

manual-test-pipeline.yml

Safe to heal aggressively — nothing real depends on a test that doesn't exist yet. Every new/changed manual test file gets its own Copilot session, sequentially.

03 — Regression suite · the safety gate

regression-heal.yml

Riskier: a bad heal here could silently mask a real app regression instead of fixing a broken new test. The classifier decides before any Copilot session for that spec exists — and two of its three outcomes never reach the healer at all.

LOCATOR_DRIFT — may heal ASSERTION_MISMATCH — never healed ENVIRONMENT_ISSUE / NEEDS_REVIEW — never healed

LOCATOR_DRIFT

Timeout on a selector, an action timeout, or a strict-mode violation — no value comparison present. A structural problem, safe to repair.

ASSERTION_MISMATCH

An Expected:/Received: pair or a toBe/toEqual/toMatch failure. Exactly the shape a real regression takes — always routed to a human, no exceptions.

NEEDS_REVIEW

Default-deny. Anything that doesn't cleanly match LOCATOR_DRIFT lands here, never the reverse — a wrong "stop" costs one review; a wrong "proceed" can hide a bug.

04 — Shared enforcement

Two independent layers under both pipelines

Neither layer alone is sufficient — Layer A is what makes the cap durable across separate sessions; Layer B is what stops the agent from routing around it within one session.
